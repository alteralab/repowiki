# using-project-skills

## 언제 쓰는가

모든 작업의 시작. 다른 스킬로 바로 들어가기 전에 이 라우터를 한 번 지난다.

## 프로세스

1. 작업의 성격을 한 문장으로 적는다 (무엇을, 왜).
2. 스킬 표에서 대응을 찾는다:
   - 새 기능·변경 구현 → `spec-driven-development`
   - 세션 시작·컨텍스트 수집 → `context-engineering`
   - 실패·버그 처리 → `eval-driven-improvement`
   - 배운 것 보존 → `memory-curation`
   - 코드베이스 지식 생성·갱신 → `repo-memory-maintenance`
3. 대응이 없으면 스킬 없이 진행하되, 같은 성격의 작업이 3회 반복되면
   REJECTIONS.md가 아니라 새 스킬 후보로 기록한다 (repository-layout.md의
   미개설 스킬 목록 참조).

## 입력과 출력

- 입력: 작업 요청.
- 출력: 선택된 스킬 이름 또는 "스킬 없음 + 공백 기록".

## 경고 신호 (red flags)

- 스킬을 고르지 않고 절차를 즉석에서 지어내고 있다.
- 두 스킬을 동시에 절반씩 따르고 있다 — 하나를 정본으로 정하라.

## 검증

- 이번 작업이 어느 스킬을 따랐는지 한 줄로 말할 수 있는가.

## 거부할 흔한 합리화

- "간단한 작업이라 스킬이 필요 없다" — 간단한지의 판정 자체가 라우팅이다.
- "스킬이 없으니 만들면서 하겠다" — 3회 반복 전의 스킬 신설은 투기다.
