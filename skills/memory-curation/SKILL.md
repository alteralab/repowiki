# memory-curation

## 언제 쓰는가

작업을 마치며 보존할 학습이 있는지 판단할 때, 또는 inbox에 후보가 쌓였을 때.

## 프로세스

1. 후보를 한 파일 한 사실로 `memory/inbox/`에 적는다.
2. 승격 3문을 건다 — 정본: `docs/policies/memory-governance.md`.
   (재사용되는가 / 신규인가 / 출처를 붙일 수 있는가)
3. 전부 예면 구획으로 옮긴다: 사실 → `semantic/`, 실패 사례 → `episodic/`,
   루틴 → `procedural/`. 하나라도 아니오면 inbox에서 지운다.
4. 기존 항목과 겹치면 새 파일 대신 기존 파일을 보강한다. 대체된 항목은
   `archive/`로 내린다.

## 입력과 출력

- 입력: 작업 중 발견한 학습 후보.
- 출력: 승격된 메모리 파일 또는 "저장 안 함 + 이유 한 줄".

## 경고 신호 (red flags)

- 대화 요약을 통째로 저장하려 한다 — memory는 transcript 저장소가 아니다.
- 코드베이스 사실을 저장하려 한다 — 그것은 repo-memory(openwiki)의 소유다.
- inbox가 늘어나기만 한다 — 큐가 아니라 로그가 되고 있다.

## 검증

- 승격된 각 파일이 3문에 어떻게 답하는지 말할 수 있는가.
- inbox가 유계인가 (판정이 끝난 후보는 지워졌는가).

## 거부할 흔한 합리화

- "쓸모 있을지 모르니 일단 저장" — 과잉 저장의 비용은 몇 달 뒤 중복과 적체로
  청구된다.
- "지우기 아까우니 archive에" — archive는 대체된 것의 자리이지 판정 회피의
  자리가 아니다.
