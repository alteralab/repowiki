# 14. Incumbent-bias audit of PLAN.md (3판)

## 0. Charge, method, and headline

**Charge.** The plan's author may have favoured old, popular, well-documented, or cheap tools. Cost is *not* a ranking axis; air-gap is pass/fail; purpose-fit (a human grasping structure and coupling through generated diagrams and pages) ranks first. Every choice is assumed wrong until evidence says otherwise.

**Method.** Each choice was audited by a dedicated research pass (web docs, GitHub release/issue API, `pip index versions`, `npm view`) plus local experiments run on 2026-09-08/09 in `scratchpad/bias-audit/` (Python 3.12.13, uv 0.11.8, node 22.17.0). Version numbers below were read from PyPI/npm/GitHub on 2026-09-08/09 unless noted.

**Headline.** Of 30 audited rows: **15 KEEP** (12 with amendments), **8 REPLACE**, **4 RE-MEASURE**, **3 KEEP-pending-a-measurement**. Five plan statements are factually wrong today and must be corrected regardless of verdict:

1. **"Leiden (networkx)" does not exist on CPU.** networkx 3.6.1 exposes `leiden_communities` only as a backend-dispatch stub; calling it raises `NotImplementedError: 'leiden_communities' is not implemented by 'networkx' backend` [실측]. Only `louvain_communities` is native.
2. **"GitLab renders Mermaid 11 only from 19.0" is wrong.** GitLab bundles `mermaid@11.13.0` since 18.11 and adds the ELK layout loader in 19.2+; the real constraints are a 2,000-character Mermaid-source cap per page and 50 blocks per page before click-to-render [sub 1].
3. **`python-hcl2 … with_meta=True` yields no line metadata.** It is a no-op stub in 8.1.4 (issue #291 open since 2026-04-09; fix PR #333 unmerged) [실측, sub 12]; the plan's Terraform span citations would silently be empty.
4. **`-c core.commitGraph=false` on `git log` has no measurable effect** on the blobless kafka clone (0.27 s either way) [sub 6]; and `--numstat` line churn is not obtainable air-gapped on a blobless clone (44.1 s with lazy fetches), so "hotspot = revisions × LOC" needs a full clone or `git backfill` of the top files.
5. **tiktoken is the wrong budget instrument for Claude.** Anthropic's own docs: Claude 4.7+ models (Opus 5 included) use a newer tokenizer producing ~30% more tokens than earlier models, `count_tokens` is free with 5,000 RPM at the lowest tier, and the vendor guidance is explicit: "Do not use `tiktoken`… It undercounts Claude tokens by ~15–20% on typical text, and by much more on code or non-English input" [웹].
