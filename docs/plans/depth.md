# 깊이 단계 — DeepWiki 수준의 문서 밀도

## 왜 이 단계가 필요한가

2026-09-09 DeepWiki apache/kafka를 브라우저로 직접 열어 실측했다. 격차는 장식이 아니라
구조다.

| 지표 | DeepWiki kafka | repowiki commons-cli |
|---|---|---|
| 페이지 | 59쪽, 3단 계층, 개념 이름 | 4쪽, 평면, 빌드 모듈 이름 |
| 페이지당 단어 | 881 (482~1,340) | 81~224 |
| 페이지당 인용 | 32건, 27단어당 1건, 80%가 줄 범위 | 5건 |
| 페이지당 도식 | 3 | 0~1 |
| 표 | 67개 (버전·설정·API·용어) | 0 |
| 읽는 파일 | 작업 트리 1,865개 (테스트 102, .github 36, docs 22 포함) | 코드만 |
| 페이지 기획 | 클러스터 기반 (Cognition 공식 문서 명시) | 빌드 모듈 |
| 인용 형태 | 분석 커밋에 고정된 소스 링크 | 경로 문자열 |

## 근본 원인 셋

**1. 쓰는 층이 소스를 읽지 않는다.** 브리핑에 구조 사실만 담기므로 쓸 수 있는 참 문장이
"X가 Y에 기댄다" 부류로 닫힌다. 구조 사실을 늘려도 이 벽은 넘지 못한다 — 범주가 다르다.

**2. 뽑은 사실을 버린다.** commons-cli에서 멤버 749개를 뽑아 놓고 브리핑에 25개만 싣는다.
호출 참조 8,901건은 수신자를 잡지 않아 전부 버린다.

**3. 페이지 단위가 빌드 모듈이다.** 모듈이 하나인 저장소는 4쪽이 상한이다.

## 판정: 근거 계약을 바꾼다

지금 계약은 "쓰는 층은 사실 JSON만 본다"이다. 이 계약이 빈 페이지의 원인이다. 새 계약은
이것이다.

> 결정층이 **무엇을 볼지** 정하고, 쓰는 층은 **본 것만 말하며 본 자리를 가리킨다.**

바뀌는 것은 브리핑에 근거 자리의 **원문**이 실린다는 것뿐이다. 나머지 강제는 그대로거나
더 세진다.

- 근거 집합은 여전히 결정적으로 고른다.
- 인용은 그 집합 안이어야 한다(기존).
- 도식과 표는 사실에서 나오고 한 글자도 못 바꾼다(기존).
- 인용 밀도 하한이 생긴다(신규).
- 인용한 자리의 원문이 그 문장을 받치는지 판정하는 검증 통과가 붙는다(신규).

약해지는 것이 아니다. 전에는 "사실에 없는 것을 못 쓴다"였고 그 결과가 빈 페이지였다.
이제는 "읽지 않은 것을 못 쓴다"이고, 읽은 자리가 인용으로 남는다.

## 단계

### A. 어댑터와 규칙 확장

ast-grep 어댑터가 메타변수를 `$NAME` 하나만 읽는다. 여러 개를 읽게 고치고, 이름과 타입을
한 매치에서 묶는 규칙을 세운다.

- `AstMatch.captures: dict[str, str]`
- 자바: 필드/파라미터/지역변수의 `(이름, 타입)`, 메서드 시그니처, 수신자 있는 호출
- 파이썬: 주석 달린 대입, 파라미터 주석, 수신자 있는 호출
- 스칼라: 같은 자리

판정 기준: commons-cli에서 `(이름→타입)` 결합이 필드 221건 중 200건 이상.

### B. 호출 그래프

수신자 이름을 스코프에서 풀어 호출 엣지를 만든다.

- 스코프: 감싸는 타입의 필드 → 감싸는 메서드의 파라미터 → 지역 변수
- `this`/`self`는 소유 타입, 수신자 없는 호출도 소유 타입
- 대문자로 시작하고 인덱스에 있으면 정적 호출
- 체인 표현식은 세고 버린다(C-REPORT-2)

산출: `CallEdge(src_type, src_member, dst_type, dst_member, span)`. 시퀀스 다이어그램과
"누가 이것을 부르는가" 표의 재료다.

판정 기준: commons-cli 호출 8,901건 중 저장소 내부 대상이 해석되는 비율을 세어 남기고,
파이썬 `ast` 오라클과 교차 검증.

### C. 반입 확대

지금은 코드만 본다. DeepWiki는 작업 트리 전체를 본다.

- 파일마다 역할을 붙인다: main / test / doc / config / ci / build / script / data
- 제외는 진짜 생성물과 벤더 사본만
- `docs/**/*.md`와 `README.md`의 제목과 문단을 자리와 함께 색인
- `*.properties`, `*.yml`, `*.conf`의 키를 자리와 함께 색인

판정 기준: kafka에서 색인 파일 수가 1,000건 이상.

### D. 페이지 기획 재설계

빌드 모듈이 아니라 클러스터가 페이지 단위다.

- 타입 그래프에 커뮤니티 검출(networkx, 입력 정렬로 결정성 확보)
- 계층: 빌드 모듈 또는 최상위 패키지 → 클러스터 → 큰 타입이나 하위 클러스터
- 이름은 지배 패키지 조각과 최상위 랭크 타입에서
- 목표 쪽수는 저장소 크기의 함수

판정 기준: commons-cli 12쪽 이상, kafka 40쪽 이상. 재실행 ARI 0.9 이상.

### E. 브리핑 심화

- 근거 자리의 원문을 브리핑에 싣는다(자리당 상한, 페이지당 예산)
- 멤버 표, API 표, 도구 사슬 표, 설정 표를 사실에서 만들어 함께 싣는다
- 형제 페이지 목록을 실어 교차 링크를 쓰게 한다

### F. 게이트

- 인용 밀도: 60단어당 1건 이상
- 분량 하한: 개념 페이지 400단어
- 도식 하한: 페이지당 1개
- 절 끝 `Sources:` 줄(결정적으로 생성)
- 근거 지지 검증: 판정자가 문장과 인용 원문을 보고 지지 여부를 판정

### G. 렌더링

- 인용을 분석 커밋에 고정된 소스 링크로(완료)
- 페이지 머리에 근거 소스 목록(완료)
- 3단 사이드바
- 교차 페이지 링크

## 각 단계의 검증

단계마다 코덱스 교차 검증을 돌린다. 규칙은 altera-rules의 C- 조항을 적용하고, 검증은
V-와 C-TEST 조항으로 별도 에이전트가 본다. 게이트는 `scripts/gate_chain.sh`.
