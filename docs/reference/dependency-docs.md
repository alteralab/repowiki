# 의존성 문서 레지스트리 (dependency docs registry)

기준일: 2026-09-09. 모든 버전과 URL은 이 날짜에 PyPI JSON API, `npm view`, `gh api`, curl로 직접 확인했다. 확인하지 못한 항목은 [unverified]로 표시했다. 구현은 기억이 아니라 아래 "정본 문서"와 "핵심 페이지"를 열어 보고 한다. 프로젝트가 `llms.txt`를 내놓으면 그것을 먼저 읽는다.

표기 규칙
- 버전 열의 날짜는 해당 버전의 첫 업로드일(PyPI) 또는 릴리스 발행일(npm, GitHub)이다.
- llms.txt 열은 `https://<docs-host>/llms.txt`와 `llms-full.txt`를 curl로 때려 본 결과다. "없음"은 404를 확인한 것이고, 바이트 수는 200 응답 본문 크기다.
- "미러" 열은 syntopicon docs-mirror에 들일 수 있는 원본 위치(마크다운 소스 경로 또는 단일 파일)를 뜻한다.

## 핀 정책

원칙: 버전의 단일 진실 원천은 락 파일이다. `data/versions.yml` 같은 별도 버전 목록은 두지 않는다. 이 문서는 "어디서 읽는가"를 적는 레지스트리이지 버전 대장이 아니다.

- `pyproject.toml`에는 하한만 적고(`>=`), 정확한 버전은 `uv.lock`이 가진다. CI와 로컬 모두 `uv sync --locked`로 설치해 락과 다르면 실패시킨다.

올리는 방법 (bump)
1. `uv lock --upgrade-package <name>` 또는 `npm update <name>`으로 한 패키지씩 올린다. 메이저 bump는 이 문서의 "12개월 내 breaking 변경" 열과 해당 프로젝트의 마이그레이션 가이드를 먼저 읽는다.
2. 단위 테스트 뒤에 반드시 acceptance golden set을 돌린다. 특히 helm/kustomize 렌더 출력, ast-grep 룰 매치 수와 def/ref 태그, python-hcl2 스팬, mermaid.parse 통과 여부처럼 출력이 그대로 골든 파일과 비교되는 항목은 버전 하나만 바뀌어도 diff가 난다. 골든 diff가 의도된 변경이면 골든을 갱신하고 커밋 메시지에 어느 의존성 때문인지 적는다.
3. 이 문서의 표에서 해당 행의 버전, 날짜, breaking 열을 갱신하고 기준일을 바꾼다.
4. 락 파일 변경과 문서 변경을 같은 커밋에 넣는다.

주의할 조합
- anthropic 1.x는 httpx2 기반이다. 같은 환경의 다른 라이브러리가 httpx 1.x를 요구하면 충돌하므로 락 해석 단계에서 걸러진다. HTTP 스택은 httpx2 한 벌이 규칙이다(PLAN §8). requests나 httpx 1.x를 요구하는 라이브러리는 그 자체로 추가 불가 사유다.
- mkdocs-material은 공식 문구상 2026-11-05까지 최소 12개월 critical/security 수정만 약속돼 있다. 그 날짜 이후 지원 보장이 없다는 전제로 결정한다(정확한 종료일은 아니다).
