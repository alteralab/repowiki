# 품질 게이트 정책

게이트 체인의 정본이다. 실행은 `scripts/gate_chain.sh`, 커밋 시점 검사는
`.pre-commit-config.yaml`. 원칙: **결정적 검사 전부가 LLM 판정보다 먼저 돌고,
사람은 마지막 관문이다.**

근거 라벨 — [실증] 심사 실증, [산업] 심사 게재이나 산업 자기 보고,
[문면] 벤더 실무 문서.

## 체인 순서

| # | 게이트 | 판정자 | 근거 |
|---|---|---|---|
| 0 | 생성 규약 (altera-rules: ruff·ast-grep) + 봉인 커밋 검사 | 결정적 | 산문으로만 금지한 규칙은 재발하고 게이트가 붙은 규칙은 재발하지 않는다 |
| 1 | `tests/unit` | 결정적 | — |
| 2 | `tests/regression` — 실패는 "동작이 바뀌었다"는 보존 신호 | 결정적 | 현재 동작 오라클은 보존용 [실증] |
| 3 | `tests/acceptance` — 수용 판정은 이 단계만 센다 | 결정적 | 수용 기준은 사람 승인분만 (SPEC) |
| 4 | 전이 원장 — 실패→통과 + acceptance 해시 변경 표시 | 결정적 | LLM 감시자 민감도 42–50% [실증] — 결정적 신호가 먼저 |
| 5 | `evals/regression` — 에이전트 동작 회귀, 통과율 ~100% | 결정적 | 반복 실패의 승격 자리. 케이스가 있는데 러너가 없으면 실패로 처리 — 조용한 생략 금지 |
| 6 | 커버리지 리포트 — **관문 아님**, 안 덮인 곳 목록이 리뷰 단서 | 결정적 | 커버리지는 단서지 목표가 아니다 [실증+규범] |
| 7 | 변경부 뮤테이션 — 살아남은 뮤턴트를 **개별로** 리뷰에 제시 | 결정적 | 점수가 아니라 개별 뮤턴트가 판정 대상 [산업] |
| 8 | 새 문맥 리뷰 — 반박 목표, 기준은 정확성·명시 요구사항 한정 | LLM | 검증자 분리 [문면], 과잉 보고 경고 [문면] |
| 9 | 사람 — 수용 기준 충족의 증거와 게이트의 잔여를 본다 | 사람 | 네 관문을 다 지나고도 남는 것이 있다 [산업] |

## 상시 봉인

- `tests/acceptance/`는 구현 중 읽기 전용 — `.claude/settings.json`의 PreToolUse
  훅이 세션에서, `scripts/seal_check.sh`가 커밋에서 강제한다. 해제는 사람 승인
  세션의 `ACCEPTANCE_UNSEAL=1`만. 근거: 테스트가 에이전트 권한 안에 있으면
  통과가 만들어진다 [실증]. **사각**: 네 치팅 경로 중 테스트 수정 하나만 닫는다
  — 특수 케이스 처리·연산자 오버로딩·상태 기록은 전이 원장과 사람 리뷰가 받는다.
  봉인 대상 목록의 단일 원천은 `scripts/sealed_paths.txt`이고 두 훅 모두 그것을
  읽는다. 세션 층은 Claude Code 어댑터다 — 다른 하네스에서는 그 하네스의 쓰기
  차단 수단으로 같은 목록을 읽는 어댑터를 재건하라(repository-layout의 하네스
  이식성 절). 재건 전까지 봉인은 커밋 층 단일 방어다.

## 금지 목록

- 커버리지 `fail_under`·뮤테이션 점수 임계치를 병합 관문으로 걸지 않는다 —
  수치를 향한 최적화가 따라오고, 커버리지를 안 늘리는 가치 있는 테스트(실측
  49%)가 버려진다 [산업].
- 코드를 쓴 에이전트에게 그 코드의 수용 테스트·테스트 플랜을 만들게 하지
  않는다 [실증].
- 검증자(리뷰) 모델을 구현 모델보다 약한 티어로 두지 않는다 [실증].
- 모델 여럿의 합의를 독립 검증으로 세지 않는다 — 오답 상관은 벤더를 갈라도
  남고, 정확한 모델일수록 크다 [실증].
- 상시 LLM 감시자를 안전망으로 세우지 않는다 [실증].
- 수용 실패를 에이전트에 되돌리는 재시도는 상한을 두고, 초과는 사람에게 —
  다중 제출은 치팅률을 함께 올린다 [실증].
- 실패한 생성 테스트는 고치지 않고 버린다 — 실패가 대상의 결함인지 단정의
  오류인지 가릴 오라클이 없다 [산업].
