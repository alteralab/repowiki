# 메모리 거버넌스

`memory/`는 큐레이션된 장기 운영 메모리다 — 대화 기록 보관소가 아니다.

## 승격 절차

모든 후보는 `memory/inbox/`를 경유한다. `semantic/`(사실·도메인 지식) ·
`episodic/`(과거 실패·사례) · `procedural/`(지속 루틴)에 직접 쓰지 않는다.
대체된 항목은 지우지 않고 `archive/`로 내린다.

## 승격 3문 — 전부 예일 때만 승격한다

1. 이 작업 맥락 **밖에서도** 재사용되는가?
2. repo-memory·docs가 이미 기록한 것의 재조합이 아닌 **신규**인가?
3. 출처(커밋·파일·세션·문서)를 붙일 수 있는가?

하나라도 아니오면 승격하지 않고 inbox에서 지운다. 과잉 저장의 비용은 몇 달
뒤 중복과 inbox 적체로 청구된다.

## 경계

- 코드베이스 사실 → `repo-memory/`(openwiki가 생성). memory에 복제하지 않는다.
- 승인된 정책·설계 → `docs/`. memory는 승인 절차를 대신하지 못한다.
- 반복 실패 → memory가 아니라 `tests/regression/`·`evals/regression/`이 먼저다.
- 반복 거절 사유 → `REJECTIONS.md` 원장이 먼저다.

여섯 구획은 고정 분류라 디렉토리가 미리 존재한다. 미리 있다는 것이 직접
쓰기의 허가가 아니다 — 경로는 언제나 inbox 경유다.
