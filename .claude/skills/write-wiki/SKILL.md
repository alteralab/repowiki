# write-wiki

## 언제 쓰는가

`repowiki`로 저장소 하나의 위키를 끝까지 만들 때. 분석부터 사이트까지 한 흐름이다.

## 프로세스

1. 분석과 계획을 한 번에 돌린다. 종료 코드가 0이어야 한다.

   ```sh
   uv run repowiki run <작업본 경로> --out <산출 디렉토리>
   ```

   0이 아니면 멈춘다. 한도 위반이나 Mermaid 파서 실패는 사실 층의 결함이고, 그 위에서 쓴
   페이지는 틀린 그림을 싣는다. 사실 층을 먼저 고친다.

2. 만들어진 쪽 목록을 본다.

   ```sh
   uv run repowiki job status --out <산출 디렉토리>
   ```

3. 쪽마다 이 셋을 반복한다.

   ```sh
   uv run repowiki job take <작업 id> --out <디렉토리>       # 이름으로 지정해 받는다
   uv run repowiki job show <작업 id> --out <디렉토리>       # 사실과 근거 목록
   uv run repowiki job show <작업 id> --out <디렉토리> --source E1,E5,E12   # 근거의 원문
   ```

   `--source`로 원문을 본 근거만 그 문장의 근거로 쓴다. 원문을 안 본 자리를 인용하면
   읽지 않은 것을 말하는 것이다.

4. `page.json`을 그 작업 디렉토리에 쓴다.

   ```json
   {
     "job_id": "...",
     "title": "...",
     "description": "한 문장",
     "tags": ["..."],
     "body_markdown": "...",
     "citations": ["E1", "E5"]
   }
   ```

   **도식과 표는 자리표시자로 넣는다.** `job show`의 "자리표시자" 절에 있는 것을 그대로 쓴다.
   손으로 옮겨 적지 않는다.

   ```
   {{diagram:TYPE-Option}}
   {{table:members-Option}}
   ```

   준 자리표시자는 하나도 빠뜨리지 않는다. 게이트가 빠진 것을 센다.

5. 제출한다. 거부되면 사유를 읽고 고쳐 다시 낸다. 거부는 임대를 푸므로 다시 `take`한다.

   ```sh
   uv run repowiki job submit <디렉토리>/.repowiki/jobs/<id>/page.json --out <디렉토리>
   ```

6. 전부 `done`이면 묶고 띄운다.

   ```sh
   uv run repowiki bundle --out <디렉토리>
   uv run repowiki site --out <디렉토리> --open
   ```

## 쪽을 쓸 때의 규범

- 목표는 700단어 이상, 60단어에 인용 한 건 이상이다. 게이트가 그 밑을 거부한다.
- 원문에서 읽은 동작을 쓴다. 구조 사실만으로 쓰면 "A가 B에 기댄다" 부류로 닫힌다.
- 소스 트리를 나열하지 않는다. 책임과 경계면 계약과 흐름과 실패 모드를 쓴다.
- 형제 페이지를 상대 링크로 건다. `job show`의 "형제 페이지" 절에 경로가 있다.
- 엠대시와 가운뎃점과 이모지를 쓰지 않는다. 이중 피동을 쓰지 않는다.

## 입력과 출력

- 입력: 작업본 경로.
- 출력: `<디렉토리>/wiki/`의 Markdown과 `<디렉토리>/site/out/`의 정적 사이트.

## 경고 신호 (red flags)

- `run`의 종료 코드를 안 보고 다음으로 넘어가고 있다.
- `job show --source` 없이 쪽을 쓰고 있다. 원문을 안 보고 쓰는 것이다.
- 표나 도식을 손으로 옮겨 적고 있다. 자리표시자가 있다.
- 게이트 거부를 피하려고 문장을 늘리고 있다. 늘릴 것은 읽은 내용이지 분량이 아니다.

## 검증

- `repowiki job status`가 전부 `done`인가.
- `bundle`이 낸 쪽 수가 계획한 작업 수와 같은가.
- 사이트가 열리고 인용 링크가 실제로 소스로 가는가.

## 거부할 흔한 합리화

- "사실이 얇으니 일반론으로 채우겠다" — 얇은 것은 사실 층의 결함이다. 그쪽을 고친다.
- "이 도식은 이 쪽에 안 어울리니 빼겠다" — 계획 층이 준 것이다. 어울리지 않으면 계획을 고친다.
- "인용을 나중에 붙이겠다" — 문장을 쓴 뒤 근거를 찾으면 근거가 문장에 맞춰진다.
